# Путь к Мечте: Приключения с Вольтиком

HTML5-игра без сборщика и внешних зависимостей.

## Сайт и автоматическая публикация

Опубликованная игра: **https://nevrozza.github.io/Game-SberKids/**.

Workflow [Check and deploy game](https://github.com/nevrozza/Game-SberKids/actions/workflows/pages.yml)
проверяет синтаксис JavaScript, кампании, события и структуру сценариев. После успешных проверок
каждый push в `artemageddon` автоматически обновляет сайт. Pull request запускает
только проверку, без публикации. На сайте размещаются только `index.html`,
`assets/`, `css/`, `data/`, `js/`; исходники проверок и служебные файлы не публикуются.

Для первой публикации администратору репозитория нужно один раз открыть
[Settings → Pages](https://github.com/nevrozza/Game-SberKids/settings/pages)
и выбрать **Build and deployment → Source → GitHub Actions**.
Если в окружении `github-pages` ограничены ветки публикации, нужно разрешить
`artemageddon` в **Settings → Environments → github-pages**.
Затем отправить изменения в `artemageddon` или повторить её workflow во вкладке
Actions. После завершения задания **Publish to GitHub Pages** сайт доступен
по адресу выше; ссылка также есть в окружении `github-pages`.

Для ручного запуска через **Run workflow** нужно, чтобы этот workflow был также
в основной ветке репозитория; при запуске выбрать `artemageddon`.
Обычный push в `artemageddon` запускает публикацию независимо от этого.

### Что открыть для конкретной правки

| Что хотите изменить | Где менять |
| --- | --- |
| Название, описание, иконку или порядок кампаний | Записи в [`data/campaigns.json`](data/campaigns.json); порядок массива `campaigns` определяет порядок внутри каждой сложности |
| Иллюстрацию кампании | Поле `image` в `data/campaigns.json`, файл изображения — в [`assets/`](assets/) |
| Категорию сложности | Поле `difficulty` той же кампании; подписи «Лёгкая», «Средняя», «Сложная» заданы в `js/campaign-data.js` |
| Сюжетную приписку о сложности | Поле `description` в `data/campaigns.json` |
| Стартовые ресурсы, прогресс, цель победы и множители | Блок `balance` кампании в `data/campaigns.json` |
| Пять иконок деталей мечты | Массив `progressIcons` в `data/campaigns.json` |
| Текст ситуации, два решения, подсказку и последствия выбора | Файл нужной кампании в [`data/events/`](data/events/), поля события и его `optA` / `optB` |
| Условие появления одной из двух версий ситуации | `condition`, `then`, `else` в том же файле событий |
| Порядок вех, случайные события и последствия решений | `data/stories/<campaign>.json` и `js/story-director.js`; сейчас подключены только для самоката |
| Сюжетные концовки | Все шесть исходов `endings` используются для сценарного самоката; у остальных кампаний пока общие финалы |
| Общие сообщения о победе и поражении | `applyDecision` и `finishGame` в `js/game.js` |
| Правила применения решений, комбо и завершения игры | `js/game.js` |
| Задания и правила мини-игр | `js/minigames.js`; их предел награды — `balance.miniGameMaxBonus` в каталоге |
| Общие палитры и цвета сцен | `js/data.js` и `artThemes` внутри `showCard` в `js/game.js` |
| Внешний вид Вольтика и иллюстрации карточек | `assets/fox.svg`, `js/graphics-vfx.js`; базовые стили — в `css/cards.css`, оформление visual — в `css/playful.css` |
| Стартовый экран и оформление | Структура — в `index.html`, стили — в `css/playful.css`, карточки кампаний создаются из JSON в `js/game.js` |
| Высоту элементов в WebView | `js/viewport.js` и переменная `--viewport-height` в `css/playful.css`; границы игрового экрана — в `css/main.css` |
| Звуки или события для СберKids WebView | `js/bridge-sound.js`; места отправки событий — в `js/game.js` |

Файлы в `data/` описывают содержимое и баланс. Код в `js/` определяет, как игра
их использует, а `index.html` и `css/` — как она выглядит. Ситуации кампаний уже
вынесены в JSON; задания мини-игр пока находятся внутри `js/minigames.js`.

В `assets/` находятся локальные SVG-иллюстрации. Сцены событий и игровой Вольтик
создаются как SVG в `js/graphics-vfx.js`. Аудиозаписей и файлов шрифтов сейчас нет:
используются системные шрифты, а звуки синтезируются через Web Audio API.

Текущие ресурсы игрока, прогресс мечты и номер карточки хранятся в памяти страницы
в `js/game.js`. Сохранения между перезагрузками пока нет. Файлы JSON во время игры
не перезаписываются.

## Запуск

Из корня репозитория:

```sh
python3 -m http.server 8000
```

Мобильное превью: http://localhost:8000/dev/mobile-preview.html — переключение
между 360 × 800, 390 × 844 и 412 × 915 CSS-пикселями в масштабе 1:1.
Страница хранится в `dev/` и не входит в публикацию GitHub Pages.

Открыть http://localhost:8000/. JSON загружается по HTTP; двойной клик по
`index.html` (`file://`) не подходит. На GitHub Pages дополнительная сборка не нужна.
Все пути относительные: игра поддерживает `/<repo>/`, `/<repo>/dev/` и
`/<repo>/versions/<tag>/`. В публикацию должны входить `index.html`, `css/`, `js/`, `data/`, `assets/`.

### Android-песочница и требования трека «Игры»

Источники требований: [сайт хакатона, трек «Игры»](https://kids.hackathon.aam.run/#tracks)
и материалы «Задачи хакатона.pdf», «СБЕРKIDS.pdf».
Игра использует HTML, CSS и JavaScript без сторонних библиотек. Игровые ресурсы
и JSON загружаются с того же сайта по относительным путям; внешних API, CDN,
аналитики и переходов на другие сайты нет. `dev/mobile-preview.html` использует
iframe только для разработки и не входит в публикуемую игру. Публичные файлы
занимают меньше 0,5 МиБ при ограничении трека 5 МБ. Звук включается действием игрока.

Игра проверяется в неизменённой [официальной Android-песочнице](https://github.com/vveidi/sber-hse-hackathon-2026-android).
Для локального сервера на порту 8000 адрес в Android Emulator — `http://10.0.2.2:8000/`.
На физическом устройстве нужен доступный ему HTTP(S)-адрес сервера или GitHub Pages.

В проверенной Android-песочнице при высоте окна 867 CSS-пикселей корневые
`height: 100%` давали нулевую высоту, а игровая область сжималась до 20 пикселей.
Ограничение подсказки через `38dvh` также скрывало её текст. Поэтому игровой экран закреплён по
границам окна, а высота иллюстраций и подсказки берётся из `visualViewport.height`
с запасным вариантом `innerHeight`. При изменении размера значение обновляется;
временное нулевое измерение не стирает последнее корректное. Сверху оставлены
56 CSS-пикселей для нативных кнопок песочницы.

При проверке нужно пройти выбор приключения, оба варианта решения, подсказку
Вольтика, мини-игру, финал и повторный выбор кампании. В журнале песочницы
проверяются события вибрации, завершения и выхода. Ошибка загрузки или показа
первой карточки оставляет каталог с доступной кнопкой повторной попытки.
Если содержимое не помещается по высоте, игровой экран прокручивается;
новое приключение начинается с верхней позиции.

Обмен с приложением идёт через `window.postMessage({ type, ...данные }, '*')`:

| Событие | Когда отправляется |
| --- | --- |
| `VIBRATION_EVENT` | При выборе решения |
| `COMPLETED_EVENT` | При первой победе за одно открытие страницы |
| `FINISH_EVENT` | При поражении, завершении без цели или последующей победе в том же открытии |
| `SHARING_EVENT` | По кнопке «Поделиться», с текстом результата |
| `CLOSE_EVENT` | По игровой кнопке выхода |

18 октября 2026 года проверены Android 14 (API 34), WebView 113.0.5672.136
и официальная песочница без изменений её исходников: открытие приключения,
решения, включение звука, видимая подсказка, мини-игра, поражение и победа
в кампании «Скейт мечты». В нативном журнале подтверждены `VIBRATION_EVENT`,
`FINISH_EVENT`, `COMPLETED_EVENT` и `SHARING_EVENT`; кнопка «Поделиться» открыла
системное меню Android. В браузере проверен запуск всех девяти кампаний
и восстановление после временной ошибки загрузки JSON и ошибки показа первой карточки.
Мобильное превью проверено на 360 × 800, 390 × 844 и 412 × 915; на узком экране
нижняя панель доступна через прокрутку. После последней правки прокрутки повторно
проверен запуск первой карточки в Android-песочнице.
Проверка на iOS и замеры 60 FPS/загрузки за 3 секунды пока не проводились.

## Кампании

`data/campaigns.json` — каталог. В выборе сначала идут лёгкие кампании, затем
средние и сложные. Внутри каждой сложности сохраняется порядок из каталога.
Группы отделены заголовками «Лёгкий старт», «Держим баланс», «Большие планы».
Фон каталога плавно меняется при прокрутке от тёмного зеленоватого через
фиолетовый к красноватому. Светлые градиенты карточек идут в том же направлении:
мятные, голубые, сиреневые и розовые. Оттенок зависит от позиции в общем списке;
при неизменном каталоге он сохраняется после обновления страницы.
Сейчас в нём девять полноценных кампаний. У каждой собственный файл событий,
иллюстрация, настройки баланса и заготовки шести концовок. Демонстрационные
записи заменены отдельными историями; всего в игре 158 событий, из них 26 условных.

| Кампания | Сложность | Событий |
| --- | --- | --- |
| Электро-Самокат | Лёгкая | 28 в пуле; длина прохождения зависит от решений |
| Игровая Приставка | Средняя | 30 |
| Умный Робо-Пёс | Сложная | 40 |
| Скейт мечты | Лёгкая | 10 |
| Телескоп и тайны неба | Лёгкая | 10 |
| Велосипед для экспедиции | Средняя | 10 |
| Настольная игра для компании | Средняя | 10 |
| Аквариум маленького океана | Сложная | 10 |
| Рюкзак для приключений | Сложная | 10 |

Карточки кампаний строятся из каталога. События загружаются
только при выборе кампании и кэшируются до перезагрузки страницы. После загрузки
рядом со сложностью показывается размер линейной колоды или «разные истории» для самоката. Пролистывание
кампаний пока не реализовано; длинный список доступен через обычную прокрутку.

Каждая кампания содержит:

- `id`: уникальный идентификатор из строчных латинских букв, цифр и дефисов;
- `name`, `icon`, `description`: название, эмодзи и описание;
- `image`: необязательный относительный путь к иллюстрации в `./assets/`;
- `difficulty`: `easy`, `medium` или `hard` — категория для подписи и будущей фильтрации;
- `progressIcons`: пять иконок деталей мечты;
- `progressSteps`: пять подписей этапов (`name` — название детали, `text` — описание текущего действия);
- `eventsFile`: путь от папки `index.html`, например `./data/events/scooter.json`;
- `storyFile`: необязательный путь `./data/stories/<id>.json`, включает сюжетный механизм;
- `balance`: индивидуальные параметры кампании;
- `endings`: сюжетные концовки; сценарный самокат использует все шесть исходов.

`image` используется на карточке выбора и в панели прогресса. Поддерживаются SVG,
PNG, WebP и JPEG. Если поле не задано или изображение не загрузилось, показывается
эмодзи `icon`. Каталог состоит из двух колонок. Первая кампания и одиночная
карточка в последнем ряду группы занимают всю ширину. Широкие карточки тоже
раскрываются по нажатию; старт приключения выполняется отдельной кнопкой.
Описание занимает столько строк, сколько помещается в свёрнутой карточке.
Сложность и небольшая стрелка ↗ расположены под описанием.

В `endings` ключи `money`, `tech`, `trust`, `team` соответствуют поражениям по
четырём ресурсам, `victory` — победе, `incomplete` — прохождению всей колоды без
нужного прогресса мечты или завершению сценария без победы. Каждая концовка содержит `title`, сюжетный `text` и полезную
подсказку `tip`. Блок необязательный; если он указан, проверяются все шесть исходов.
Самокат использует эти тексты для победы, завершения без цели и поражения по каждому
из четырёх ресурсов. Остальные восемь кампаний пока показывают прежние общие финалы.

Категория сложности сама не меняет баланс. Две кампании с `hard` могут иметь разные
параметры. Характер испытания раскрывается в `description` через игровую завязку
и намёк на сложность: «Уютная разминка перед большими приключениями» или
«Каждый ход на вес золота!». Описание редактируется вручную и не меняет баланс.
Множители и стартовые значения остаются в `balance`; отдельного числового грейда нет.

В `balance` находятся:

| Поле | Назначение |
| --- | --- |
| `initialStats` | Начальные `money` (копилка), `tech` (бодрость), `trust` (дружба), `team` (смекалка); каждый от 1 до 100 |
| `initialDream` | Начальный прогресс мечты от 0 до 100 |
| `winDream` | Требуемый прогресс для победы от 1 до 100 |
| `miniGameMaxBonus` | Максимальный бонус одной мини-игры, от 0 до 100 |
| `multipliers.resourceLoss` | Множитель отрицательных изменений четырёх ресурсов |
| `multipliers.resourceGain` | Множитель положительных изменений четырёх ресурсов |
| `multipliers.dreamLoss` | Множитель потерь прогресса мечты |
| `multipliers.dreamGain` | Множитель прироста прогресса мечты |

Множители неотрицательные. Эффект умножается с сохранением знака и округляется
через `Math.round`. Подсказки при свайпе учитывают те же множители и округление;
нулевой эффект не показывает стрелку. Затем ресурсы ограничиваются диапазоном 0–100.
Комбо добавляет свой бонус после применения множителя прогресса. Награды мини-игр не умножаются
этими коэффициентами: их предел задаётся отдельно через `miniGameMaxBonus`.
У линейных кампаний победа проверяется в конце колоды, у сюжетных — после финальной
вехи и всех обязательных продолжений. Ноль любого ресурса означает поражение.

## События

В `data/events/<campaign>.json` хранится объект с массивом `events`. Порядок
элементов задаёт порядок линейного прохождения. При наличии `storyFile` события
выбираются по ID из сюжетного описания. У каждого события есть постоянный
уникальный внутри файла `id`; не меняйте существующие id при редактировании текста.
Для новых событий удобно использовать префикс кампании, например `scooter-021`.

Обычное событие содержит `id`, `type`, `emoji`, `title`, `desc`, `tip`, `optA`, `optB`.
Допустимые категории `type`: `shop`, `friend`, `scam`, `tech`, `quiz`.
Цвета и иллюстрации выбирает интерфейс по категории, в JSON они не дублируются.

Каждое решение (`optA` и `optB`) содержит:

```json
{
  "text": "Отложу в копилку на самокат",
  "effects": { "money": 12, "tech": 0, "trust": -4, "team": 8 },
  "dream": 7,
  "mascot": "happy",
  "msg": "Копилка пополнилась, но без торта друзья взгрустнули!"
}
```

Эффекты — базовые значения до множителей кампании, от −100 до 100. Для `mascot`
допустимы `happy`, `think`, `scared`. Как и раньше, `happy` увеличивает комбо,
`scared` сбрасывает его и на карточках `scam` учитывается как ошибка мошенничества.
Левое и правое решения случайно переставляются движком; не привязывайте смысл к стороне.

Условное событие вместо обычных полей карточки содержит:

```text
id
condition: { "stat": "money", "operator": ">=", "value": 55 }
then: { ...полная карточка без id... }
else: { ...полная карточка без id... }
```

`condition.stat` — один из четырёх ресурсов. Операторы: `>=`, `<=`, `>`, `<`, `==`, `!=`;
значение от 0 до 100. Условие проверяется перед показом карточки по текущему состоянию,
затем выбирается `then` или `else`. Обе версии имеют те же поля, что обычная карточка,
кроме `id`. JavaScript, функции и вложенные условия в JSON не используются.
Пример целиком есть в `data/events/scooter.json`, событие `scooter-009`.

## Сюжетный механизм самоката

`storyFile` указан только у самоката. Остальные восемь кампаний сохраняют свои
линейные колоды и порядок событий. Сценарий самоката описан в
`data/stories/scooter.json`, а тексты и эффекты карточек — в
`data/events/scooter.json`.

Приключение начинается с `scooter-001`, затем следует выбор маршрута `002` и его
непосредственное продолжение: помощь друзей (`017`) или план со взрослым (`016`).
Соответствующие факты могут открыть дополнительную сцену `021` или `022`.

В истории пять этапов, соответствующих панели мечты: «Колёса», «Дека»,
«Управление», «Аккумулятор» и «Первый заезд». Их обязательные карточки
`004 → 023 → 008 → 024 → 020` становятся доступны соответственно при прогрессе
мечты 15%, 30%, 45%, 60% и 75% и после предыдущей вехи. Готовая веха показывается
следующей приоритетной карточкой; следующий этап открывается только после решения
на ней. Стартовый прогресс — 15%, поэтому первые четыре карточки включают начало,
выбор маршрута, его продолжение и веху колёс. Большой прирост может сразу достичь
нескольких порогов: заработанный прогресс сохраняется, но каждая веха всё равно
показывается отдельно и в нужном порядке. Заполнение каждого участка шкалы
считается по порогу этого же этапа, поэтому полный кружок совпадает с готовностью
его карточки; пройденные этапы не откатываются. После решения на вехе её порог
становится нижней границей самого прогресса мечты: например, после деки он уже
не опустится ниже 30%. Ошибки могут уменьшать накопления до следующей вехи,
но повторный выбор пройденной детали не появляется. Закрепление действует внутри
текущего прохождения; ноль любого ресурса всё ещё означает поражение, а новая
попытка начинается заново. Крупные награды за решения сохранены; комбо, множители
и награды мини-игр не уменьшены. У выбора крепежа есть безопасный вариант подготовки без
траты монет: готовая веха не вынуждает терять последний положительный ресурс.

Между готовыми вехами выбираются подходящие ситуации из пула. Четыре бытовые
карточки можно встретить повторно: они помогают пополнить монеты, бодрость,
дружбу или смекалку. Для них задан интервал в три хода между повторами;
при значении соответствующего ресурса не выше 25 срабатывает условие срочности.
Уникальные сюжетные сцены повторно не выбираются. Существующие `condition/then/else`
определяют вариант условной сцены по состоянию на момент показа.

Пока игрок не выбрал решение, повторный запрос возвращает ту же сцену; отмена
свайпа не меняет сюжет. Факты фиксируются по логическому `optA`/`optB` независимо
от перестановки кнопок. Запланированное продолжение показывается перед новым
случайным выбором. При нуле любого ресурса история заканчивается поражением.
Защитный предел в 60 решений завершает затянувшуюся историю без победы; он не
задаёт обычную длину прохождения и не заменяет финальную веху.

Основные поля сценария версии 2:

| Поле | Назначение |
| --- | --- |
| `version`, `opening`, `facts`, `maxTurns` | Версия 2, ID первой карточки, объявленные факты и защитный предел решений |
| `chapters[].id/title` | Идентификатор и название этапа для счётчика хода |
| `chapters[].completeWhen` | Условия готовности обязательной вехи |
| `chapters[].pool/repeatable/milestone` | Уникальные события, повторяемые события и обязательная веха этапа |
| `events.<id>.requires` | Условия: `all`/`none` для фактов, `stats` для ресурсов и `dream` |
| `events.<id>.weight/boosts` | Базовый вес и множители `{when, factor}` при подходящем состоянии |
| `events.<id>.urgentWhen/cooldown` | Условие срочного восстановления и интервал между повторами |
| `events.<id>.choices.optA/optB` | Установить `set`, удалить `clear` факты, назначить `followUp` |

Правило в `stats`: `{stat, operator, value}`, например
`{"stat":"money","operator":"<=","value":25}`. Все условия одного блока
выполняются вместе. Вехи и продолжения зарезервированы для своих ролей;
продолжения не образуют циклов и не требуют фактов, которые не гарантированы
предыдущим решением.

`StoryDirector.create(config, events, {seed})` создаёт независимое прохождение;
`next({stats, dreamPct})` выбирает текущую карточку, `commit('optA'|'optB')`
фиксирует решение. `isPriorityCardReady` позволяет проверить готовность вехи или
продолжения без изменения состояния выбора. `getStatus()` сообщает текущую главу,
факты, историю, `milestonesCompleted`, нижнюю границу прогресса `checkpoint`,
`completed` и `exhausted`. Генератор
случайности отделён от эффектов и мини-игр; без явного `seed` новое открытие
получает случайное начальное значение.

Мини-игры назначаются после каждых четырёх решений, но откладываются, пока не
показаны готовые приоритетные вехи и продолжения. Награда начисляется до выбора
следующей случайной карточки; после финала мини-игра не запускается. В интерфейсе
показаны номер хода и текущий этап, а размер пула не задаёт длину партии.

## Добавление кампании

1. Создать `data/events/<новое-имя>.json` с непустым списком событий.
2. Добавить запись с новым `id` в `data/campaigns.json`, настроить баланс и `eventsFile`.
3. Выполнить проверки и открыть игру. Менять HTML или движок не нужно.

## Проверки (Node.js 20+)

```sh
node scripts/check-data.cjs
node scripts/check-viewport.cjs
node scripts/check-rendering.cjs
```

`check-viewport.cjs` проверяет начальную высоту окна, изменение размера,
восстановление после нулевого измерения и запасной вариант без `visualViewport`.
`check-rendering.cjs` проверяет повторное использование SVG Вольтика, смену
настроения и направления взгляда, эффекты предпросмотра ресурсов и отсутствие
повторных записей DOM при неизменном результате.
Проверка данных и синтаксиса JavaScript входит в GitHub Actions перед публикацией.
`check-data.cjs` также проверяет структуру подключённых сценариев.
Проверки высоты WebView и рендеринга нужно запускать локально указанными выше командами.

`check-data.cjs` находит пропущенные поля, опечатки в ключах, повторные id, недопустимые
условия и коэффициенты. Игра использует те же правила при загрузке. При сетевой
ошибке или неверных данных она остаётся на экране выбора с кнопкой повтора.
На загрузку каждого JSON отводится 15 секунд, включая получение тела ответа.
Если время истекло, запрос отменяется, выбор кампаний снова доступен и можно
повторить загрузку. Неудачная попытка не остаётся в кэше событий.
Подробности ошибки доступны в консоли браузера.

`js/data.js` содержит только общие палитры интерфейса. Загрузчик и правила
формата находятся в `js/campaign-data.js`, игровой цикл — в `js/game.js`.

## Производительность

Во время свайпа Вольтик использует прежний SVG, пока не меняется настроение;
поворот, следование за карточкой и взгляд обновляются отдельно. Предпросмотр
ресурсов меняет классы и текст только при изменении результата. Анимации игры
приостанавливаются под непрозрачным каталогом и возобновляются при старте;
невидимая обучающая подсказка тоже ставится на паузу.

При сравнении на Android 14 / WebView 113 в одном эмуляторе три коротких свайпа
на первой карточке давали 27 пересозданий SVG до оптимизации и 0 после неё.
Изменений классов и текста в показателях стало 72 вместо 424. Это счётчики работы
интерфейса, а не измерение FPS или гарантия быстродействия реального телефона.
Для проверки слабых устройств нужны замеры на физическом Android-телефоне:
отдельно каталог, свайпы, мини-игры и несколько полных прохождений подряд.
